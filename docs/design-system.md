# Monido Design System

The visual language is the brand violet on violet-tinted neutrals with flat surfaces. The source of truth is `src/styles/tokens.css`; this document is a reference. Update it when you add a token, component or class.

Net worth history uses three straight 2px lines, calendar gaps, a shared React tooltip and a visually hidden accessible summary. Its 3/6/12-month presets count calendar slots inclusively; period selection, units and series belong to the History section of Overview and do not alter the global period. Money/percent axes and selected-range growth identify their actual baseline dates; no missing month becomes zero. Invalid percent bases have an explanation and an amount-mode recovery action. Keyboard arrows include missing months; the selected-month summary remains available without Canvas. Tiny nonzero changes and CAGR use localized bounds, such as <0.1% or >−0.1%, instead of rounding to zero.

The account button is quiet: a round avatar on `--track` (initials for a named account, a neutral icon for family-password access), the name and a decorative chevron, with no fill until hover or while open. Its 264px menu says who is signed in, the rights in one line ("Full access" when nothing is missing, otherwise what they can and cannot do and whom to ask) and the way out, as a row under a `--rule`. Escape and an outside click close it; the demo shows no account menu. The menu scrolls within short screens.

ThemedChart renders each builder's explicit accessible description in React so privacy changes replace old labels immediately. ECharts automatic descriptions/decals are not used. Legend and mark-line components register only in their consuming lazy charts; all charts keep the same core singleton.

## Where the design lives

- **This file** is the one source of the rules: tokens and their roles, themes, components, shared classes, screen patterns.
- **`/design/`** (local, `npm run dev`) draws every shared element with its `use:` line, from `design/registry.ts`; tests keep it complete.
- **`CLAUDE.md`** repeats the shortest rules an agent needs on every task.
- **`DESIGN.md`** (local, gitignored) describes the visual world for the impeccable skill (tokens in its frontmatter) and copies no section of this file (`tests/docs/designDocs.test.ts` checks it where it exists).

Where they disagree, this file wins and the others are corrected.

## The catalog

Every shared element is drawn, with its states, on a local page: `npm run dev`, then `http://localhost:5173/design/` (with the slash), with switches for the theme, privacy mode and the language. Its tokens come with their values in the shown theme and, under each, the usage note written as the comment closing the token's line in `tokens.css` (a new token gets one). Browse entries by purpose. Each live preview runs in its own viewport at 390, 768 or 1440 CSS pixels. Each entry has a direct link (for example, `/design/#e-Switch`); the code button opens its source and lets you copy its registry context. The page draws `design/registry.ts`: one entry per element, its `use` line saying what it is for and what to use instead. Before writing an element, find it there (`grep -rn "use:" design/`); a new shared element gets its entry in the same change, which `tests/design/registry.test.tsx` checks. The duplicates section, linked when groups are open, draws each group of today's duplicates beside the canonical element it is to merge into (the same classes the ratchet below freezes).

**The ratchet.** A class named like a shared primitive (its words include empty, note, kpi, table, delta, label, link or title for a block; note, delta, empty, table or link for an element) may live only in the owner stylesheets (`tokens.css`, `controls.css`, `ui-surfaces.css`, `record-list.css`, `progress-track.css`, `disclosure.css`, `record-charts.css`); and a native `<table>` only in the files that draw one today. `tests/styles/duplicateRatchet.test.ts` keeps today's duplicates in `FROZEN` (grouped by the canonical class they merge into) and accidental matches in `ALLOWED` (each with its reason); `tests/styles/sharedUi.test.ts` keeps the table files. A merge PR moves a group onto its canonical class, removes it from `FROZEN` and lowers the pinned count; a new look-alike fails `npm run check`.

## 1. Tokens

### 1.1 Color: roles

The values of every token, light and dark, are in `src/styles/tokens.css`: the `:root` block (light) and the `:root[data-theme="dark"]` block. This section gives the roles.

| Role | Tokens | Rule |
|---|---|---|
| Accent | `--primary`, `--primary-hover`, `--primary-text`; the label on a `--primary` fill is `--on-primary` | The brand violet means "here and now": see the violet rule in §1.2 |
| "Bad" | `--error`, `--error-text`, tints `-16/-24` | Only the "Critical" assessment and errors. Not expenses and not debt amounts |
| "Attention" | `--warning*` | "Needs work", warnings |
| "Good" | `--success*` | "Good" and "Excellent" (told apart by the label), a positive change |
| Heatmap steps | `--asset-re` and `--text-1` mixed into `--paper` (20/40/60%, 20/30/40%) | Only the Accounts "Month by month" grid (`.acc-heat__cell--up-N` / `--down-N`): a month's balance change, a rise in the asset teal and a fall in grey (a sign, not an assessment), in thirds of the largest change; the text on them stays `--text-1`, and a cell's value and title say the figure, so the tint is never the only sign. Not an assessment elsewhere |
| Neutral | `--text-1/2/3`, `--secondary` | Expenses, debts, member names, reference values |
| Chart categories | `--chart-1 … --chart-7` | Segments and series; they are not assessments |
| Asset types | `--asset-re*`, `--asset-br*`, `--asset-bk*`, `--asset-ot`, each with its `-ink` | The Assets page's map, waterfall and holdings: a type is one hue, its holdings tones of it by rank |

- **Text in a semantic color is only `--X-text`** (`--primary-text`, `--secondary-text`, `--success-text`, `--error-text`, `--warning-text`, `--info-text`; ≥4.5:1 on `--paper`, `--bg` and the 8/16/24% tints in both themes). The base `--X` are for backgrounds, borders, fills and icons.
- **Text levels:** `--text-1` text, `--text-2` secondary text, `--text-3` labels and the sidebar's group names (≥4.5:1). They, the rules and the field edge are alphas of `--ink-ch` (in dark a violet off-white, so text-1 is not pure white); every text level is ≥4.5:1 on `--paper`, `--bg` and `--raised`. A field's edge is `--input-border` (≥3:1 against `--paper` and `--bg`), not `--rule`.
- **A signed change** is text in ink (`.delta`; beside its period word, `.delta-pair` with `.delta-pair__label`), not a chip and not a status colour: a rise or a fall is a fact, not an assessment.
- `--error-fill` / `--error-fill-hover`: the danger button fill for white text. `--on-fill` (white in both themes) is the label on those fills and on the warning icon; `--on-primary` is painted only on a `--primary` fill (guarded).
- `--brand` (the light `--primary` in both themes) is the logo square; `LogoMark` strokes the Monido mark with `--on-fill`: an M whose middle sags into a nest (money + nido) and whose right leg rises higher than the left (growth); flat feet on the baseline like Onest's terminals, round peaks, on a continuous-corner tile. The favicon has its own heavier 16 px cut.
- `--member-1 … --member-4` colour people (the first series hues plus a grey) in the order violet, amber, teal, grey, so neighbouring members are at least 60° of hue apart (`designTokens.test.ts`); `--chart-1 … --chart-6` are violet (= `--primary`), teal, amber and three greys with a trace of the violet (the lightest/darkest ≥3:1 on `--paper`); `--chart-7` is a bank blue.
- **The asset palette** (`--asset-*`, used through `.asset-tone--*` in `assets.css`, which sets `--tone` and `--tone-ink`: a map tile paints both, a swatch, a share bar, a waterfall bar and a holdings group's rule the fill; a holding keeps the same tone on the map, the waterfall and the holdings list, picked by its rank by value within its type in `src/pages/assets/tones.ts`): real estate a teal (`--asset-re`, `-re-2`), brokerage an amber (`--asset-br`, `-2`, `-3`), bank a blue (`--asset-bk` = `--chart-7`, `-2`, `-3`), other holdings (crypto) a neutral grey (`--asset-ot`); the largest holding of a type takes the base tone. The base tones are darker than `--chart-2`/`--chart-3` so white reads on them; in dark the order turns round (the base tones are the light ones). Each tone names its ink `--asset-<tone>-ink`, either `--on-fill` or `--asset-ink-light` (`#14131A`, a shade deeper in dark), at ≥4.5:1 in both themes (`designTokens.test.ts`). No violet among them: on the map every tile is a holding, and a violet one would read as the selected item. On the rest of the page violet stays here-and-now: the waterfall's end tick (the current total), the history's shaded period and its current point, the links. A change in the composition and the holdings is ink, rise or fall, as in the headline; an owner is the member tint of their initial (`.lane__avatar--tinted`), as on the Overview's Whose assets.
- Surfaces: `--bg` the pearl ground of the page and the sidebar (a deep violet-grey in dark, not black), `--paper` tiles and cards, one tone step above it, `--track`. `--raised` is one step above `--paper`: tile hover, menus and dialogs (white in light, lifted by `--shadow-float`; one step lighter than `--paper` in dark, because a shadow barely shows on a dark ground). `--rule` is the only line: the hairline inside a tile (table rows, chart gridlines, the row rules of lists and dialogs, the ghost button's edge), raised under more contrast; `--bar` / `--bar-soft` are the past on charts (bars, the past part of a line; the comb's strokes, empty frames). `--tooltip-bg` / `--tooltip-text` are the ink of the tooltip and the toast.

### 1.2 Surfaces and shadows

This section describes the pearl design code, the target the components move to; the tokens are in place, and the sentences marked "today" say where the components have not moved yet.

| Surface | Class or token | When |
|---|---|---|
| Card | `.card` (`Card`): `--paper` on `--bg`, `--r-card`, no border, no shadow; title 15/500 with an optional chip at the right | Every block: key numbers, statuses, insights, tables, lists, charts; the "Records" and "Settings" panels too (`.admin-panel`, `.admin-table-wrap`, `.settings-section`, `.side-list`, `.form-card`, `.disclosure-group`: `--paper`, no border); under `prefers-contrast: more` and `forced-colors: active` these surfaces, `.notice` and the month-close queue's current pill get a 1px `--rule` edge back |
| Tile | `--paper`, `--r-tile` | The sidebar's places and inner panels: a step below the card |
| Raised | `--raised` | The step above paper: tile hover, menus and dialogs (the toast is ink: `--tooltip-bg`) |
| Rule | `--rule`, 1px | The only line, and it lives in tables (row rules, chart gridlines); never a card edge |
| Float | `--shadow-float` | Only menus, dialogs, toasts and the phone drawer; nothing else has a shadow |

The violet rule: violet means "here and now".

| | |
|---|---|
| Yes | the selected tile and the selected second-floor row; the one primary button on a screen; the current (or selected) period on a chart: last bar, end dot, the last segment of a line, the selected month's band; the selected and the open month in the comb (its other strokes are `--bar-soft`), the open month in the ribbon; progress fills and ring segments; the focus ring; links; the logo |
| No | icons, group labels, page titles, figures, deltas (ink: a sign is not an assessment), the count badge (warning tint), the past on any chart, the second and third data series (ink greys), and a second button on the same screen (it is white or quiet) |

An insight has no left stripe: severity lives in its chip. Shadows: `--shadow-float` on what floats (dialogs, menus, toasts), on `--raised` with no border (forced colours drop the shadow, so there and under more contrast a 1px `--rule` edge comes back); the phone drawer floats on `--shadow-lg`, the chart tooltip on `--shadow-md`; nothing rests on a shadow. There are no coloured (primary) shadows: the primary button, the active pill and the active sidebar item are flat.
Backgrounds: `--bg` page, `--paper` card, `--track` bar track, `--hover`. Buttons are round (`--r-pill`), 36px tall: the primary `.btn--primary` (`--primary` with `--on-primary`; `.btn__well`, a 24px round `--raised` disc with the icon in `--primary-text`, carries a plus or a check inside it), the white `.btn--ghost` (`--paper` with a `--rule` hairline so it stays visible on a card, `--raised` on hover), the quiet `.btn--quiet` (no fill, `--text-2`; hover `--paper` on the ground, `--track` on a `--paper` surface through `--quiet-hover`), the outlined `.btn--danger` and the filled `.btn--danger-solid`. `--ghost-bg` is the fill of a white button (`.btn--ghost`, and of `.btn--danger`), `--paper` by default; a raised surface (a menu, a dialog, the Close-month bar) sets it to `--raised`, so the button takes that surface's fill instead of the darker card one.
The card height comes from its content: the rows of the `.rg-*` grids align to the top.

Shell (the target): the 248px sidebar stands on the `--bg` ground with no border: the logo row, a 2×4 grid of tiles for the enabled places (`Overview, Close month, Assets, Loans, Income and expenses, Goals, Financial health, Advisor`; the current tile is a `--primary` fill), the second floor (the area's sub-pages; on the Overview, what needs doing), and at the foot the account button, the Settings row, the version and the theme control. The compact 72px mode is one column of icon tiles with tooltips; below 1200px the drawer keeps the grid; the phone's More sheet is the same tiles, three across, Settings as the ninth, and the bottom bar stays: a `--paper` strip with no border, the current item `--primary-text` at 500. The demo panel and, on a phone, the notices hang from the title row's foot (`.title-row` is their anchor), so they land under the end cluster however the title wraps. There is no top bar. A title row takes its place: the page title (24/600) with a 14px subtitle (the data month, its age, the FX rate) and, at the right, the screen's primary action and the currency pills, then the demo pill, the notices and the privacy eye; nothing pins. One flex-wrap rule lays it out on every page, with no breakpoints and no page names: the title keeps whole words and is never shrunk below its own width, so when the line is short the action cluster and then the tools wrap to the next line (the tools stay right-aligned); the data line is a row of its own, and on a phone the action cluster goes under it. The phone drawer floats on `--shadow-lg`; windows (`.form-dialog`, `.confirm-dialog`, `.prompt-dialog`) and menus have no edge. The Overview trend draws the past in ink (`.trend__plot`, `--text-2`), the last segment over it in violet (`.trend__plot--now`, `--primary`) and marks the last point with a dot (`.trend__dot`, `--primary`, HTML so the stretched plot does not turn it into an ellipse); its gridlines are `--rule` and may carry a caption of its window (`.trend__caption`); the open-month notice is a one-line `.notice` (`Notice`): a `--paper` card with a bold lead-in (`.notice__title`), the sentence (`.notice__text`) and the action at the right, no stripe. The Overview trend's y labels have their own lane (`.trend__y-lane` sizes the column to the widest label). The `.pills` track is `--track`; hover on an item is a `--rule` edge and `--text-1`, because `--hover` is almost the same colour as `--track`.

### 1.3 Typography

The font is Onest. The shared scale includes compact task-form help and headings; weights are 400, 500 and 600:

| Token | px | Where |
|---|---|---|
| `--fs-meta` | 12 | axes and meta lines (the period, the source under a value) |
| `--fs-help` | 13 | task-form supporting text, 20px line height |
| `--fs-section` | 16 | compact task-form group headings, 600 weight and 24px line height |
| `--fs-sm` | 14 | labels, tables, chips |
| `--fs-md` | 15 | text, card title (`.card-hd`, 500) |
| `--fs-field` | 16 | text in fields only (`.admin-input`, `.admin-select`): below 16px iOS zooms into a focused field |
| `--fs-lg` | 18 | section title (`.section-label`, 600) |
| `--fs-xl` | 24 | KPI value (`-0.01em`), page title (600) |
| `--fs-2xl` | 36 | the page's main number |

Weights: 400 body text, 500 labels, buttons and card titles, 600 page and section titles. Figures are 400 everywhere: the main number (`.hl__value`, one per page: never broken across lines, a scrolling region when wider than its column), KPI and comparison values (`.stat__value`, `.status-compact__value`), changes (`.delta`) and value lists (`.financial-values dd`); size, not weight, makes a number the main one. Tabular digits are only the `.num` class, table cells (`.td-num`), amount fields (`.admin-input--num`), the trend's axis labels (`.trend__y`, so the lane does not jitter) and the demo countdown (`.demo-pill`, so the pill keeps its width as the seconds tick): Onest's proportional "1" is narrow, and tabular figures would open gaps in a large figure like "$1,146,244" (measured: 142px proportional vs 171px tabular at 32px).
Numbers in the interface go through `fmtNum` / `fmtPct` / `fmtMonths`, and an amount in a record's own currency through `fmtMoney` (`src/lib/formatters.ts`): the decimal separator of the current language, a typographic minus, `—` instead of a missing value.

Chart metadata uses the 12px role and grows with root text size. SVG frames measure their container in text-sized units, without a height cap; narrow charts reduce tick density and move long captions below the plot. Canvas axes, legends and tooltips resolve their rem roles to pixels. While Onest loads, Canvas uses an explicit system font; switching to Onest also refreshes cached text measurements.

At enlarged text sizes, navigation, controls, cards and record panels reflow to keep labels and amounts readable. Account calendars divide into two six-month sections when needed, preserving every cell. Financial fields use `--fs-field`; long instructions have a 72ch measure and 1.55 line height.

Money on the dashboard goes only through `DashboardContext`'s `fmt`: privacy mode masks it (`•••`). Prompts for Claude use `fmtPlain`, which keeps the real amounts; when privacy is on the prompt dialog requires an explicit reveal before building or displaying them.

Touch pointers use44px minimum actions; multiline button labels grow beyond that minimum. Dense month/account tracks scroll locally, preserve their original bar geometry and keep the selected month visible. In narrow workspaces list amounts move below names; long isolated amounts remain complete in keyboard-focusable horizontal scroll regions. Safe-area insets extend shell padding and the bottom bar while preserving zero-inset spacing. Form option widths follow their labels in narrow dialog containers.

### 1.4 Spacing and radii

The scale: `--sp-05` 4, `--sp-1` 8, `--sp-15` 12, `--sp-2` 16, `--sp-3` 24, `--sp-4` 32, `--sp-6` 48. The card's inner padding is `--card-pad` (24px, 16px on a phone).
Raw px in `padding`, `margin`, `gap` are forbidden (except `0` and `1px`).

Rhythm: 4–12px inside a card, 16px between the cards of a group, 48px between sections.

Record details are inline-size containers. Their four-column KPI strip becomes two columns at46rem of panel width and one at25rem; these thresholds refer to the panel, not the window. The equity composition bar moves below its figures when the panel narrows. Loan early payments, the payment schedule and property valuations scroll horizontally inside a positioned `.admin-table-scroll` region; their portaled row menus remain outside clipping. Compact account heatmaps use numbered months with full localized month titles. Settings use `--card-pad`, and the inflation fields wrap according to available width.

Long goal statuses and the Advisor connection action wrap instead of widening the page. Goal rings reflow with a104px minimum column. Confirmation dialogs retain16px viewport insets and scroll internally on short screens; the Claude question window also allows outer scrolling when enlarged text exceeds its inner panel.

WindowChart displays at most five scale ticks, deriving a readable presentation scale when its supplied ticks are denser; the domain history and monetary deltas are unchanged. Overview's final net-column label is right-aligned inside the canvas. Projection tooltips are confined, width-bounded and wrap their rows. Property change captions reserve space for their localized text, with per-year values retained in the valuation table and bar titles; single-valuation amounts choose a position inside the plot. A waterfall reserves at least96px for numerical marks; when name/value lanes would consume that budget, each row puts its name and complete value above the mark, wrapping long values. Waterfall text estimates and row spacing follow the computed label font size, including enlarged text preferences.


Radii: `--r-control` 10px (fields), `--r-tile` 14px (tiles, inner panels), `--r-card` 16px (cards, menus), `--r-dialog` 16px (dialogs: as round as a card), `--r-pill` 999px (fully round: buttons, chips, the `.pills` well and its items, the demo's countdown pill), `--r-mark` 4px (small marks: the Accounts heatmap cells and the chart keys' swatches).

## 2. Themes

`<html data-theme="light|dark">`. The theme is a per-device choice System / Light / Dark. `ThemeChoice` sets it: a radio group of three icons (monitor, sun, moon) on the `.pills` look at the foot of the sidebar, on one row with the short version. Each icon is named by `title` and `aria-label`, and the keyboard follows the radio pattern. The compact rail stacks the same icons; on a phone they are 44px targets in the drawer that More opens; the demo uses the same control. The setup screen has no sidebar and a one-row phone header, so it keeps `ThemeToggle`, a sun/moon `.icon-btn` through the same `setMode`: one click goes to the theme not on screen (from System, the opposite of the device's), then Light ↔ Dark; its icon and accessible name are the theme it gives. The way back to System is `ThemeChoice`, in the sidebar after setup. System is the default and follows `prefers-color-scheme` live; the choice is kept in `localStorage` under `ff-theme` (a blocked storage means System). A blocking script `public/theme-init.js` (an external file: the CSP forbids inline scripts) reads the same key and sets the attribute and `color-scheme` before the first paint; after that `ThemeProvider` (`src/lib/ThemeContext.tsx`) applies the choice and, in System, follows the device. Components do not know about the theme: the dark theme overrides only the tokens of §1.1–1.2.

Charts: `useChartTheme()` registers the ECharts theme `vuexy-light`/`vuexy-dark` from the tokens and returns its name; pass it as `theme` and `key`. The chart rules in the theme (`buildChartTheme`): the gridlines are the `--rule` of the tables, four of them (`splitNumber: 4`), no axis lines or ticks, labels `--text-3`; bars are square at the foot with a 2px radius at the top; pie segments are parted by a 3px `--paper` edge; legend swatches are rectangles; the series palette is `--chart-1…6`. On a time series the past is ink and only the current point is violet: `AreaChart` draws net worth's past in `--bar` and its last segment and end dot in `--chart-1` (a second series over the same months, so the axis tooltip and the accessible summary are unchanged; assets and loans keep their hue whole), with markers only at the end. The Income and expenses band chart (`BandChart`) is plain SVG on the same rules: income and expenses in ink, violet only on the period, the selected points and the period's bars.

Goals have no hue (`src/pages/goals/`, plain SVG through `useChartFrame`): the plan and independence's 8% forecast are ink (`--chart-4`, 2.5px), the pace that makes the deadline dashed `--chart-6`, the 5–11% return range a `--chart-6` band (18% fill, no stroke), the target a dotted `--text-2` rule, the deadline a thin `--text-2` line; the amount by the deadline is a hollow ink point, the month reached a filled one. In «How the goals share» the chosen goal is `--chart-4` and the others alternate `--chart-6` and `--bar`, so violet never floods the chart. Violet is only today (the line and its dot), the progress fills, the selected list row (`--primary-16`) and «Update saved»; `--success-text` / `--warning-text` only on a goal's assessment (on time, late, short), never on a figure.

## Content restraint: remove interface noise

Settings → General is the approved reference. Apply these rules when reviewing each subsequent screen, in both languages and themes.

- Every persistent sentence must help the user choose, explain scope or a non-obvious consequence, or prevent a likely mistake. Remove copy that only narrates the interface.
- Say each fact once. Omit subtitles that list the visible sections and descriptions that repeat field labels. Do not replace removed text with decorative icons, badges or extra containers.
- Keep automatic controls quiet at rest. No permanent “Autosave” or “Saved” labels. Show pending feedback beside the affected control, one transient success confirmation, and an actionable error that remains until resolved. A shared request must not display duplicate statuses beside unrelated fields. Preserve accessible status announcements.
- Keep field labels persistent and accessible. A short optional example may live in an empty field; required instructions, constraints and errors must not depend on a placeholder, hover or focus.
- Keep consequential explanations visible: which people a setting affects, whether account amounts change, and what cannot be calculated without a value. Keep format previews when they reveal a non-obvious effect of a choice.
- Put secondary calculation methodology in the existing disclosure. Do not hide information needed to make the immediate decision. Shorten wording without removing financial meaning.
- Use colored notices only for meaningful states and their consequences. Ordinary help stays plain. Do not repeat a notice's message in surrounding text or rely on color alone.
- Empty collections get one concise explanation and an available next action, without an empty table header. Preserve explicit Save/Cancel where users edit financial drafts.
- Review the whole screen at rest, while editing, after success and after failure. Check that shortened RU/EN text remains clear on phones and that removing copy also removes its unused spacing.

Review question: **If this text disappears, does the user lose information needed to choose, act or recover?** If not, remove it. Minimalism must not remove validation, financial consequences, accessible names or error recovery.

## Shared presentation ownership

Before adding a visual element, reuse its existing component or stylesheet.
Pages may arrange shared elements; their appearance belongs to the shared owner.
Use explicit variants for real differences, migrate every equivalent caller and
remove the superseded rule. Do not create a page-specific clone or recolor a
primary button through an ancestor selector.

| Pattern | Owner and supported variation |
| --- | --- |
| Fields and selects | `Field`, `Select`, `controls.css`; standard/inset/comfortable fields, navigation select |
| Inline errors | `FieldError`; Field's stable `error` slot or existing useFieldError validation state |
| Loading and load failures | `Loading` never shows the word, only to a screen reader: no className is a page (`PageSkeleton`), a className is a section's box with three `.skeleton-lines`, `quiet` is the boot before the shell; `PageError` with the existing retry callbacks |
| Skeletons | Existing `Skeleton`/`PageSkeleton`; predictable content loading, not saving actions |
| Continuous progress | `ProgressTrack`, `progress-track.css`; compact/tall; not composition or bullet charts |
| Chart legends | `record-charts.css`; common samples, series colors and dashes owned by the chart |
| Dialogs and floating panels | `Dialog`, `ui-surfaces.css`; separate widths, placement and interaction behavior |
| Entity list rows | `record-list.css`; explicit account/property layouts, domain calculations in callers |
| Scrollable choices | `SegmentedPills overflow="scroll"`, shared `pills--scroll` style |
| Surfaces and actions | Shared paper surface, `Card plain`, muted button, subtle Notice, square/compact control scopes |

`tests/styles/sharedUi.test.ts` protects these ownership boundaries as part of
`npm run check`. It does not detect every possible semantic duplicate: reviewing
new components against this inventory remains necessary. Preserve labels, focus,
validation, portal boundaries, mobile layouts and dark-mode contrast when
extending a shared owner.

Kept separate on purpose: status, warning and stepper `details` elements (their
lifecycle differs from `Disclosure`); bullet charts, composition bars, range markers
and `SegmentedBar` (not `ProgressTrack`); `OptionPicker`, `ThemeChoice` and period
buttons (not `SegmentedPills`); menus keep their own positioning, portals and keyboard
handling over `floating-surface`; neutral `acc-tag` metadata is not a status `Chip`.
