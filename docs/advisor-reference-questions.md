# Advisor reference questions

A fixed set of conversations that every change of the advisor's guide, tools or calculations must pass. Each case is asked in a **new chat** in claude.ai with the Monido connector on, against the demo family (`npm run db:seed -- --reset-demo`, base currency USD). Ask in the family's language; the cases below are written in English.

The expected figures are what the server's own tools return for the demo family; they move with the date (the demo data is generated relative to today). The figures below are from one past run: recompute them before a run. Seed a scratch `DATA_DIR` with the demo family (`DATA_DIR=<scratch> npm run db:seed -- --reset-demo`), start a local server on it and choose Password in web setup (12 to 128 characters), sign in with `curl -c <cookie-file>`, and call `POST /api/advisor/tools/<name>` with `curl -b <cookie-file>` with the case's scenario. A figure in Claude's answer that no tool returned is a failure.

## What every answer must do

- Answer in the user's language, in plain words; no tool codes (`caution`, `amber`, `save_up`, `no_mandatory`…).
- Call `get_family_overview` first; evaluate with `evaluate_purchase` / `evaluate_goal`, never compute money itself. Calling `get_advisor_guide` is not required and not graded: claude.ai may never call it, so the rules must reach Claude through the tool descriptions and the `answerRules` of the results. Note whether it was called.
- Ask for every missing required parameter in one short question, and never assume one.
- Every figure is quoted exactly as a tool gave it, with no rounding and no sums, differences or estimates of Claude's own; the currency of every amount is named.
- No scenario of Claude's own: only the user's and the tool's alternatives, each evaluated with the tool before it is mentioned.
- When there is a verdict: the first line is one short sentence: the risk in words and the main reason with its figure; it never contradicts the tool's risk level. At most two closing sentences.
- "Save up", "a later date" or "an earlier date" only when the tool lists it; nothing invented.
- Figures in the number format of the user's language, digits exact (`8 816,79` in Russian, not `8816.79`); months stay months, never "almost three years".
- A goal that is late: what the nearer goals take and until when (`takenAhead`) and what the goal needs (`requiredMonthly`, an even spread from now); never "save this from now" while `takenAhead` is present.
- An offer to send to the family only after a concrete plan of the user's own, as one short separate line. Sending is two steps: `preview_proposal` first, its `card.text` shown to the user as it is, and `propose_to_family` with the `draftId` only after the user's explicit yes to that card. The title and the question carry no figures, not even spelled out.

## How goal dates are projected

The goal plan runs month by month from today, up to 1,200 months. Each month the savings go to the open goals in deadline order (the input order for equal deadlines), each taking its even share of what is left up to its deadline; a goal past its deadline takes all it still needs. A goal reached stops taking, and its share goes to the next goals in the following months, so a goal behind a nearer one gets only what the nearer goals leave until they are reached (nothing, when they take all the savings; in the demo, the renovation behind the emergency fund and Japan gets nothing until April 2028). The date a goal is reached is the month its remainder hits zero: on track if that is the deadline month or earlier, at risk if later, unreachable past the horizon. A credit's payment lowers the savings only for its term. The alternatives (save up, a later or an earlier date) search at most 30 years (360 months) ahead; a later or an earlier date may move a goal that is already late, and the answer must say so.

## Running them without claude.ai

The same tools answer at `/api/advisor/tools/<name>` behind the site's session, so the cases can also be run by Claude Code (or any agent) against that local server in password mode. Run them as claude.ai runs them: each case is a fresh agent that sees **only the tool list and the tool descriptions** (`GET /api/advisor/tools`: each tool's name, description and input schema) and how to call a tool with `curl`. It is **not** told to read `get_advisor_guide`, and it gets neither the guide nor the MCP server's instructions: claude.ai may never read them, so a run that hands them over tests a better-informed Claude than the real one. It answers in the family's language and gets scripted replies to its questions. Grade each transcript against the table above and against the tools' own answers.

R13 needs sign-in through Telegram even for the preview: `preview_proposal` is gated by the council like the sends, so in password mode it answers `advisor.council_unavailable` (409) and nothing can be previewed. A password-mode run checks only that the agent says in words that sending needs sign-in through Telegram and does not offer to send again. The whole of R13 needs a server with Telegram sign-in selected in the web UI (a bot token, and a member who can manage users and settings with a linked Telegram account), a session signed in through the bot and handed to the agent as its cookie, and an author with the vote right and a linked Telegram account (else `advisor.not_a_voter`). Up to the preview it writes nothing; the send creates the proposal and delivers its cards through the bot, so run that step only where the linked accounts are your own test accounts.
